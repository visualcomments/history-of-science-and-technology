# Исследовательский модуль: физические данные и соревнование

[`physics-dataset-competition/`](../physics-dataset-competition/README.md) —
дополнительный исследовательский модуль курса. Он продолжает линию
[`capstone-aviation-radar/`](../capstone-aviation-radar/README.md) от
публикации архивного датасета к полному исследовательскому конвейеру
работы с научными данными: **поиск → сбор → оцифровка → схема →
валидация → публикация → соревнование**.

Модуль не заменяет тридцать занятий курса, а служит практической
площадкой: он опирается на профильные занятия по аэродинамике,
радиолокации и вычислительным системам (18, 25, 27, 29) и на капстоун,
но не входит в фиксированный порядок занятий
([`syllabus.md`](../syllabus.md)). Капстоун доводит архивные данные
авиации и радиолокации до Kaggle-датасета и community-соревнования;
этот модуль расширяет ту же работу на четыре домена и добавляет строгую
схему записи, провенанс и воспроизводимый benchmark.

## Назначение

- научить смешанную (физика / ML / аналитика / backend) аудиторию полному
  циклу работы с научными данными;
- собрать, верифицировать и опубликовать воспроизводимый датасет
  экспериментальных данных по четырём доменам;
- провести Kaggle community competition и опубликовать benchmark с честным
  public/private-разбиением и защитой от утечек;
- отработать агентную разработку: централизованный агент «архитектор + PM»
  и локальные агенты участников с PR, ревью и quality gates.

## Домены

| Домен | Что собирается | Ключевые метрики |
|---|---|---|
| **AERO** | аэродинамика: поляры, Cx/Cy(α), распределение давления | RMSE по Cx/Cy, физическая согласованность |
| **STR** | теория прочности: σ–ε кривые, пределы прочности/текучести, усталость | RMSE по σ, MAE по N циклов |
| **RADAR** | радиолокация: ЭПР (RCS), диаграммы, SNR | RMSE (dB), калибровка |
| **CTRL** | системы управления: переходные процессы, АЧХ/ФЧХ, запасы устойчивости | RMSE/MAE, устойчивость предсказания |

Каждая запись обязана иметь физические единицы (SI или явно указанные),
оценку неопределённости и цепочку провенанса. Валидатор записей —
`physics-dataset-competition/src/physics_ds/schema/validate.py`:

```bash
python physics-dataset-competition/src/physics_ds/schema/validate.py <records.jsonl>
python physics-dataset-competition/src/physics_ds/schema/validate.py --selftest
```

Benchmark — `physics-dataset-competition/benchmark/run.py`.

## Фазы (roadmap)

Фазы и критерии приёмки соответствуют проектному документу модуля
(DESIGN §17):

| Фаза | Срок | Результат | Критерии приёмки |
|---|---|---|---|
| **P0. Setup** | 2 нед | репозиторий, CI, секреты, группы | все гейты зелёные на скелете; PII-скан пуст |
| **P1. A1 Collection** | осень, 12 нед | bronze/silver v1.0.0 | ≥ целевого числа записей; копирайт-гейт пройден; зачёт A1 |
| **P2. A2 Validation** | весна, 8 нед | v1.1.0 + golden + splits | validation report; 0 утечек; единицы проверены |
| **P3. A3 Competition** | весна, 8 нед | Kaggle competition + benchmark | private LB стабилен; benchmark воспроизводим |
| **P4. Sustain** | далее | поддержка | SLA на алерты; отчёты; ротация |

Общие критерии приёмки: воспроизводимость (README за < 30 мин), отсутствие
нарушений PII/копирайта, версионирование артефактов, настроенная
наблюдаемость.

## Quality gates

Обязательные проверки CI (DESIGN §9.2):

1. **lint/format** (ruff, black, prettier, markdownlint);
2. **schema validation** (jsonschema) для всех записей;
3. **unit tests** (pytest, покрытие ≥ 70 % для `src/`);
4. **data validation** (Pandera/Great Expectations): типы, диапазоны,
   единицы, дубликаты;
5. **PII scan** (regex + энтропия) на все публичные файлы;
6. **copyright gate**: у каждой записи допустимый `rights.copyright_status`;
7. **link checker** (внешние ссылки живы);
8. **reproducibility smoke test**: сборка gold-датасета на фикстуре;
9. **Kaggle/HF dry-run** (для publish-PR).

## Rubric

Оценка задания — 100 баллов (DESIGN §13.1):

| Критерий | Вес | Отлично (4) | Хорошо (3) | Удовл. (2) | Не сдано (0–1) |
|---|---|---|---|---|---|
| Полнота данных | 25 | ≥ цели, все домены | 80–99 % | 60–79 % | < 60 % |
| Корректность/единицы | 20 | все проверены, uncertainty | мелкие правки | заметные ошибки | грубые ошибки |
| Provenance | 15 | полная цепочка PROV | незначит. пробелы | частично | отсутствует |
| Copyright/права | 15 | всё классифицировано | единичные unknown | много unknown | нарушения |
| Качество кода/CI | 15 | все гейты зелёные | 1 жёлтый | 2+ жёлтых | не проходит |
| Документация | 10 | README + card + CHANGELOG | почти полная | фрагментарно | нет |

Порог зачёта — ≥ 60 баллов и отсутствие нарушений copyright/PII
(иначе 0).

## RACI

Матрица ответственности (DESIGN §13.3): R — responsible, A — accountable,
C — consulted, I — informed.

| Активность | PM-агент | E1/E2 | D1 | D2 | D3 |
|---|---|---|---|---|---|
| План/backlog | A/R | C | I | I | I |
| Сбор данных | I | C | R | C | I |
| Схема/нормализация | I | C | C | A/R | C |
| Copyright-гейт | I | A/R | C | C | I |
| Валидация/golden set | I | C | C | A/R | C |
| Baseline/benchmark | I | C | I | C | A/R |
| Kaggle-публикация | A | C | I | C | R |
| Инциденты | A/R | C | C | C | C |

Роли: **PM-агент** — координация и backlog; **E1/E2** — эксперты по доменам
(AERO/STR и RADAR/CTRL) и копирайт-гейту; **D1** — сбор/оцифровка;
**D2** — схема, нормализация, golden set; **D3** — baseline, метрики,
Kaggle.
