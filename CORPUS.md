# CORPUS — корпус источников курса

Курс опирается на **верифицированный корпус** — библиотеку текстов,
по которым проверяются все цитаты и работает поиск. Сам репозиторий
GitHub включает только карту источников, правила цитирования и отчёт
проверки; полные тексты лежат рядом с копией репозитория в рабочем
пространстве (на любом хосте), а индекс/эмбеддинги распространяются
через **Google Диск** (`docs/GOOGLE-DRIVE.md`).

## Где живёт корпус

Путь к корпусу задаётся переменной окружения `COURSE_CORPUS_ROOT`:

```
<COURSE_CORPUS_ROOT>/
├── txt/          ← текстовые версии источников (UTF-8, *.txt)
├── index/        ← RAG-индекс: annoy.index, embeddings.npy, chunks.jsonl, config.json
├── sources/      ← исходные файлы (pdf/epub/djvu) каталога литературы
├── scripts/      ← рабочие скрипты локали (поиск, сборка, верификация)
└── catalog/      ← каталог литературы, план загрузки, логи
```

Инструменты репозитория (`make search`, `make verify`,
`tools/*.py`) используют `COURSE_CORPUS_ROOT` и не требуют фиксированных
путей. Индекс корпуса (Annoy/эмбеддинги/чанки, ~86 МБ архив)
распространяется через **Google Диск**: `make index-fetch URL="<ссылка>"`
скачает архив, проверит SHA-256 и развернёт в `COURSE_CORPUS_ROOT/index/`
(см. `docs/GOOGLE-DRIVE.md`).

## Получение корпуса (обязательный шаг развёртывания)

Курс **не готов к занятиям**, пока корпус не установлен: без текстов
цитируемый фрагмент нечем подтвердить. Поэтому получение корпуса — часть
развёртывания, а не отложенное действие обучающегося.

```
make corpus-fetch          # индекс + тексты, с проверкой SHA-256
make corpus-status         # только отчёт, ничего не скачивает
make corpus-fetch URL="<ссылка на индекс>" TEXTS_URL="<ссылка на тексты>"
make corpus-fetch FORCE=1  # переустановить, даже если корпус уже есть
```

Без `make` (любая ОС, включая Windows):

```
python tools/corpus_fetch.py
python tools/corpus_fetch.py --status
python tools/corpus_fetch.py --index-only     # только индекс
python tools/corpus_fetch.py --texts-only     # только тексты
```

`make index-fetch` сохранён для совместимости и делает то же, что
`make corpus-fetch`.

### Два артефакта, два манифеста

| Артефакт | Манифест | Что внутри |
|---|---|---|
| Индекс | `index-manifest.json` | `annoy.index`, `embeddings.npy`, `chunks.jsonl`, `config.json` |
| **Тексты** | `corpus-manifest.json` | `txt/*.txt` — тексты, по которым проверяются цитаты |

Оба нужны. Индекс без текстов находит фрагмент, но подтвердить его нечем,
поэтому `corpus_fetch.py` считает корпус неполным и говорит об этом прямо.

`corpus-manifest.example.json` — образец манифеста текстов; заполняется после
публикации архива (размер, SHA-256 архива, хэши каждого файла, `url`).

### Что делает загрузчик

1. Берёт ссылку из `--url` / `COURSE_INDEX_URL` (`--texts-url` /
   `COURSE_CORPUS_URL` для текстов), иначе — из манифеста.
2. Скачивает с учётом особенностей Google Диска (страница подтверждения для
   больших файлов; `gdown`, если установлен).
3. **Проверяет SHA-256 архива И каждого файла** до распаковки. Несовпадение —
   жёсткая остановка: артефакт повреждён, устарел или это не тот архив.
   Если хэшей нет — структурная проверка с явной пометкой «хэшем НЕ
   проверялось».
4. Устанавливает атомарно (`index/` → `index_old/`), чтобы неудачная загрузка
   не оставила полуразрушенный корпус на месте рабочего.

### Если что-то не так

| Симптом | Что делать |
|---|---|
| корпус отсутствует | `make corpus-fetch` |
| ссылка не работает / нет доступа | сообщить сопровождающему курса; **не** подставлять свою ссылку |
| не совпала контрольная сумма | остановиться, не использовать загрузку, сообщить ожидаемый и полученный хэш |
| `index/` есть, `txt/` пуст | догрузить тексты: цитаты проверять нечем |
| нет сети | сказать прямо; работать статически по `citations.md`, повторить позже |

CI (`tools/validate_course.py`) проверяет, что манифест с заполненным `url`
несёт `sha256` и хэши файлов: манифест без хэшей не отличает повреждённую
загрузку от исправной и валит сборку.

## Как собрать корпус

Корпус строится из каталога литературы (`catalog/`) стандартной
процедурой: загрузка источников → конвертация в `txt/` (включая DjVu) →
сборка RAG-индекса (`index/`). Конкретные команды зависят от локали и
задокументированы в каталоге; в репозитории хранится только карта
источников (`citations.md`) и верификация цитат.

## Что дают инструменты агента

| Инструмент | Что делает |
|---|---|
| `tools/rag_search.py` | локальный семантический поиск (нужен `COURSE_CORPUS_ROOT`) |
| `tools/verify_quotes.py` | проверка всех цитат курса по корпусу |
| `tools/session_material.py`, `tools/assignment_brief.py` | материал/задания занятия |
| `tools/status.py` | состояние репозитория и корпуса |
| `tools/rag_api.py`, `tools/serve_api.ps1` | локальный RAG-API (опционально) |

## Состав и лицензионная чистота

Корпус состоит из источников публичного достояния и документов
правительства США/NASA (public domain). Современные коммерческие издания
в корпус не включаются; появление недопустимых файлов выявляется на
этапе верификации и чистки индекса (`index_prune`). Список разрешённых
источников — в `citations.md`.
