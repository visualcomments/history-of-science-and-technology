# Участие в курсе (CONTRIBUTING)

Курс «История России: история и философия науки и технологий» — это открытый
проект: репозиторий **и есть** учебный материал. Полезная работа участников
остаётся в проекте для следующей группы и попадает в открытые датасеты на
HuggingFace.

> Этот файл — авторитетное руководство по участию. Агент-соученик (botai) читает
> его и **предлагает описанное здесь первое задание** в начале работы
> (см. `botai/course.json`, `contribution.enabled=true`).

## С чего начать: первое задание (роль «эксперт»)

**`assignments/00-first-contribution/`** — базовое задание, с которого начинают
все: собрать **3 записи** с **количественными результатами/измерениями** из
исторических источников (число + единица) по схеме проекта. Полный текст, роли,
критерий приёмки и оценка — в `assignments/00-first-contribution/README.md`.

Коротко:
- проще всего — через агента opencode: команда `/expert-histsci`;
- либо вручную помощником `dataset-schema/expert_record.py` (берёт дословную цитату);
- результат — `assignments/00-first-contribution/submissions/records-<ник>.jsonl`;
- проверка — `dataset-schema/validate.py` (`errors=0`).

Сдача: откройте pull request (или, если есть право записи, коммит в `main`).
После попадания в `main` workflow `submit-dataset` проверяет submissions,
объединяет их и обновляет датасет на HuggingFace.

## Роли

| Роль | Вклад | Остаётся в проекте |
|---|---|---|
| **Эксперт** | разметка данных: измерения, результаты, проверка цитат | записи датасета, проверенные цитаты |
| **Разработчик** | код, тесты, CI, воспроизводимый запуск | принятый PR, зелёный CI |
| **Исследователь** *(опц.)* | метод, постановка задачи соревнования | описанный метод |

## Исследовательский трек: физические данные (опционально, отдельное задание)

Это **необязательное отдельное задание** для роли «эксперт» в модуле
`physics-dataset-competition`. Оно **не заменяет** первое задание выше и
использует **физическую схему** модуля
(`physics-dataset-competition/configs/schema/record.schema.json`), а не
универсальную схему первого вклада
(`assignments/00-first-contribution/`). Полные руководства —
`physics-dataset-competition/docs/EXPERT-GUIDE.md` (подробная пошаговая
инструкция эксперту и агенту), `physics-dataset-competition/docs/EXPERT-ASSIGNMENT.md`
(краткая процедура) и
`physics-dataset-competition/docs/OPENCODE-EXPERT-PROMPT.md` (правила
агента); краткий маршрут — `docs/opencode-physics-expert.md`.

Кратко: задание выполняется **агентом**, эксперт подтверждает результат.

Запуск в OpenCode (из корня репозитория): команда `/phys-expert` или фраза
«начинайте выполнение первого задания для эксперта». Агент работает в режиме
«делает почти всё сам, эксперт валидирует», через один оркестратор
`physics-dataset-competition/scripts/run_assignment.py` (домен —
`AERO`/`STR`/`RADAR`/`CTRL`):

1. **Поиск метаданных** в официальных API (OpenAlex/arXiv/Crossref) — ничего
   не скачивается.
2. **Авто-фильтр прав**: остаются только `redistributable` кандидаты с
   allow-list хостов; отбракованные попадают в `skipped` с причинами.
3. **Lawful-загрузка** разрешённых источников — файлы только в
   `.local/physics-bronze/` (вне git).
4. **Авто-извлечение** чисел с единицами из скачанного текста (черновик).
5. **Сборка записей** по канонической схеме.
6. **Выборочная проверка** (детерминированная) — критерий 0 ошибок.
7. **Пакет `validation-bundle.json`** — что именно эксперт должен подтвердить.

Эксперт в конце **проверяет и подтверждает** числа (единицы, знаки, условия) по
первоисточнику; при замечаниях исправление делается новой записью (append-only)
через `scripts/correct.py`. Затем — **Hub-PR** в датасет
`chaotic-good-project/physics-experiment-records` (`--publish`; dry-run по
умолчанию). Токен — только через окружение `HF_TOKEN`. Для зачёта достаточно
URL созданного PR в отчёте; PR не мержится экспертом.

Полные руководства: `physics-dataset-competition/docs/EXPERT-GUIDE.md` и
`docs/opencode-physics-expert.md`.

### Локальная статья или книга: калибровочная сессия в OpenCode

Если эксперт уже имеет законный локальный доступ к статье/книге и хочет
калибровать агента в чате OpenCode, используется команда
`/local-phys-expert`. Агент извлекает кандидаты, эксперт указывает явные
ошибки и одобряет финальный ответ; append-only обезличенный журнал затем может
быть отправлен PR в `top-papers/physics-agent-calibrations`. Полный туториал:
`physics-dataset-competition/docs/OPENCODE-LOCAL-EXPERT-TUTORIAL.md`.

Исходные PDF/сканы, локальные пути, полный текст, персональные данные и токены
не сохраняются и не публикуются. `HF_TOKEN` настраивается экспертом только в
защищённом окружении OpenCode и не передаётся в чате.

Raw-источники, секреты и персональные данные не коммитятся; права не
угадываются (детали — в руководствах модуля выше).

## Как внести изменение

1. Определитесь с ролью и возьмите задачу из `assignments/00-first-contribution/`.
2. Ветка от `main` → изменение → проверка → pull request.
3. В описании PR: что и зачем, кому помогает, как проверить, источники и **где
   использовался ИИ**.

Правила репозитория:
- изменения в `main` — по возможности через PR; история не переписывается,
  force-push запрещён;
- порядок занятий фиксирован (`make order-check`) — его нельзя менять «под
  обучающегося»;
- `make verify` — цитаты только из корпуса, дословно, с координатами
  «файл · фрагмент #N»;
- не коммитить секреты, персональные данные, файлы без ясной лицензии.
