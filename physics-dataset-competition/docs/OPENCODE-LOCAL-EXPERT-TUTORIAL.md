# Туториал: экспертная калибровка по локальной статье или книге в OpenCode

Этот маршрут предназначен для экспертов, которые работают **только в чате
OpenCode**. Участник передаёт агенту путь или локальную ссылку на статью/книгу,
агент извлекает данные эксперимента, эксперт проверяет их в чате, а затем
агент сохраняет обезличенную цепочку исправлений для датасета
[`top-papers/physics-agent-calibrations`](https://huggingface.co/datasets/top-papers/physics-agent-calibrations).

Это калибровочное задание физического модуля. Оно не заменяет базовое первое
задание курса в `assignments/00-first-contribution/`.

## Что понадобится

1. Локальная копия репозитория
   [`visualcomments/history-of-science-and-technology`](https://github.com/visualcomments/history-of-science-and-technology).
2. OpenCode, открытый **в корне этой локальной копии**.
3. Статья/книга, к которой у вас есть законный доступ, и знание её правового
   статуса. Допускаются PDF, сканы, изображения и текст, если ваш OpenCode умеет
   прочитать этот локальный файл.
4. Для финального PR — ваш персональный fine-grained Hugging Face токен с правом
   `write` **только** на `top-papers/physics-agent-calibrations`, заранее
   настроенный в защищённом окружении OpenCode как `HF_TOKEN`.

Никогда не вставляйте токен в чат, Markdown, файл, PR или аргумент команды.
Если в вашем варианте OpenCode нельзя безопасно передать `HF_TOKEN` среде
агента, остановитесь на `dry-run` и попросите сопровождающего курса настроить
секрет. Не передавайте токен преподавателю или другому участнику.

Если материал находится вне папки репозитория, OpenCode запросит разрешение на
чтение внешней директории. Разрешайте только конкретный путь к материалу; не
давайте агенту доступ ко всему домашнему каталогу, облачному диску или папке с
секретами.

## Шаг 0. Установка харнесса и запуск OpenCode

Харнесс уже находится в репозитории курса:

- `physics-dataset-competition/harness/` — проверяемый harness;
- `physics-dataset-competition/calibration/` — append-only журнал сессии;
- `physics-dataset-competition/scripts/calibration_session.py` — создание,
  проверка и экспорт журнала.

Сделайте один раз:

1. Получите локальную копию репозитория курса обычным способом (clone или fork
   + clone).
2. Откройте эту папку в OpenCode.
3. После обновления репозитория **полностью закройте и заново откройте
   OpenCode**: он загружает `.opencode/agent/` и `.opencode/command/` только при
   старте.
4. В чате попросите агента выполнить проверку установки:

   > Проверь, что локальный harness и калибровочные тесты установлены: запусти
   > `python -m pytest physics-dataset-competition/tests/calibration -q` и
   > кратко сообщи результат.

   Ожидаемый результат — все тесты проходят. Если они не проходят, не начинайте
   работу со статьёй: попросите агента показать ошибку и обратитесь к
   сопровождающему курса.

## Шаг 1. Запуск сессии в чате

Введите команду:

```text
/local-phys-expert
```

Агент сначала спросит согласие. После согласия сообщите ему одним сообщением:

```text
Материал: /абсолютный/путь/к/статье.pdf
Тип: article
Название: <название по титульному листу>
Домен: AERO | STR | RADAR | CTRL
Права: <например, я имею законный доступ; не разрешаю публиковать текст/сканы>
Сессия: <латиница-цифры-дефис, например radar-ivan-01>
Задача: извлеки численные результаты эксперимента, единицы, условия и источник
для каждого значения.
```

Можно дать локальную ссылку вместо пути, если она открывается именно на вашем
устройстве. Не вставляйте в чат полный текст платной статьи, ключи доступа,
пароли или токены. Агент подтверждает, что файл доступен; если нет — он пишет
`blocked`, а вы указываете корректный путь или выбираете другой материал.

### Как выбрать домен

| Домен | Примеры данных |
| --- | --- |
| `AERO` | `Re`, `Ma`, угол атаки, `Cx`, `Cy`, давление |
| `STR` | напряжение, деформация, модуль, усталость |
| `RADAR` | RCS, частота, угол, SNR, диаграмма направленности |
| `CTRL` | `Kp`, `Ki`, `Kd`, переходный процесс, АЧХ/ФЧХ |

## Шаг 2. Проверка первого ответа агента

Агент создаёт рабочую папку только в `.local/calib/<session_id>/` и в чате
показывает таблицу кандидатов. Для каждого кандидата проверьте по первоисточнику:

1. верно ли прочитано число и знак;
2. верна ли единица и масштаб (например, `cm/s`, а не `m/s`);
3. принадлежат ли условия именно этому эксперименту;
4. точна ли координата: страница, таблица, рисунок, подпись или диапазон строк;
5. не перепутаны ли серии графика, оси или методы;
6. не пропущены ли неопределённость, диапазон или важная оговорка автора.

Если всё верно, напишите в чате:

```text
Одобряю извлечение: проверены значения, единицы, условия и координаты.
```

Если есть ошибка, дайте конкретную обратную связь, например:

```text
Не одобряю. Стр. 4, рис. 2, серия B: агент указал 2.4 m/s, но ось подписана
cm/s; значение — 24 cm/s. Добавь условие «температура 293 K» из подписи.
```

Не пишите «поправь всё» без указания ошибки: сессия полезна для обучения только
тогда, когда исправление проверяемо.

## Шаг 3. Раунды исправления

При замечании агент добавляет в журнал экспертский разбор, затем новый
`correction` и исправленный `agent_answer`. Он не перезаписывает предыдущий
ответ. Повторяйте проверку в чате до явного одобрения.

Порядок журнала фиксирован:

```text
task → agent_answer → expert_review →
(correction → agent_answer → expert_review)* → final
```

Сессия без вашего явного одобрения не может быть экспортирована или опубликована.

## Шаг 4. Валидация и обезличенный экспорт

После вашего одобрения попросите агента:

```text
Проверь калибровочную сессию, экспортируй её в обезличенный JSONL и покажи
краткую сводку: число событий, число исправлений, отсутствие локальных путей,
длину выдержек и результат валидации. Пока не публикуй.
```

Агент обязан выполнить валидатор и экспорт. Экспорт:

- сохраняет только метаданные источника, короткую выдержку (не более 200
  символов по умолчанию) и ход исправлений;
- удаляет локальные пути;
- редактирует типичные токены/ключи;
- не включает PDF, сканы, изображения или полный текст.

Проверьте, что в сводке нет личных путей, токенов, e-mail, контактов или
неразрешённых фрагментов текста. Если они есть — **не публикуйте**; попросите
агента остановить работу и сообщите сопровождающему курса.

## Шаг 5. PR в Hugging Face

Только после проверки экспорта и отдельного решения эксперта напишите:

```text
Экспорт проверен. Создай PR в top-papers/physics-agent-calibrations из
обезличенного JSONL для сессии <session_id>. Не выполняй merge.
```

Агент использует `HF_TOKEN` только из защищённого окружения, создаёт ветку вида
`expert/<session_id>` и возвращает URL PR. Он не должен выводить токен и не
должен выполнять merge.

Если токен не настроен, это штатный результат: попросите агент выполнить только
`dry-run`. Настройку секрета делает сам эксперт через защищённые настройки своего
OpenCode/операционной среды; токен не передаётся через чат.

## Что не разрешено

- Коммитить или публиковать исходный PDF, скан, изображение, локальный путь или
  полный текст статьи/книги.
- Обходить paywall, DRM, robots.txt или условия использования.
- Утверждать данные, права или координаты без проверки первоисточника.
- Публиковать неутверждённую сессию.
- Передавать кому-либо персональный Hugging Face токен.

## Готовый первый запрос

После запуска `/local-phys-expert` можно вставить:

```text
Начинаем. Материал локально: <абсолютный путь или локальная ссылка>.
Тип: article. Название: <название>. Домен: <AERO|STR|RADAR|CTRL>.
Права: <краткое реальное основание>. Сессия: <латинский-slug>.
Извлеки все явно подтверждённые численные результаты эксперимента, сохрани для
каждого значение, единицу, условия и страницу/таблицу/рисунок. Не утверждай
неоднозначные значения: вынеси их отдельным списком вопросов для меня.
```

## Когда работа считается завершённой

1. Эксперт явно одобрил итоговый ответ агента.
2. Валидация JSONL-сессии прошла без ошибок.
3. Экспорт не содержит локальных путей, секретов, персональных данных и сырых
   материалов.
4. Создан PR в `top-papers/physics-agent-calibrations` **или** задокументирован
   `dry-run`, если защищённый `HF_TOKEN` недоступен.
