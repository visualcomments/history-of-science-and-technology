# Задания модуля (пошаговая система)

Цель — пройти весь путь «архивная книга → Kaggle-датасет → соревнование
сообщества». Работа ведётся командами (2–4 человека) по этапам; каждый этап
сдаётся как результат (deliverable) и оценивается по рубрике. Перед стартом —
прочитать правовой документ `10-legal-public-domain.md` и проставить правовой
чек-лист по выбранному источнику.

## Этап 0. Организация и выбор темы

- Сформируйте команду и выберите домен: **радиолокация/электромагнитные
  волны** или **аэродинамика/беспилотная авиация** (можно **баллистика /
  прочность**).
- Составьте карту источников: какие архивные книги по теме доступны в
  открытых архивах и в **корпусе курса** (txt/). Укажите минимум 3 кандидата.

**Результат:** файл `01-plan.md`: команда, домен, список книг-кандидатов,
риски (качество скана, отсутствие таблиц, права).

## Этап 1. Правовой аудит источника (правовая прозрачность)

Для выбранной книги заполните чек-лист (из `10-legal-public-domain.md`) и
оформите справку:

1. Автор(ы) и год смерти (для перевода — переводчик);
2. Год первого издания;
3. Расчёт срока охраны (РФ «жизнь + 70» / США «до 1930» / Бернский минимум);
4. Отсутствие отдельного © на введение/послесловие/иллюстрации скана;
5. Итоговый статус («Public domain», «охраняется», «нужна проверка»).

**Результат:** файл `02-license.md` со справкой и выводом. Без положительного
статуса идти дальше нельзя (отредактируйте, пока не пройдёт проверку
преподавателем).

## Этап 2. Извлечение «сырых» данных (data archaeology)

- Определите, какие именно таблицы/ряды/измерения подходят под задачу
  (например: развёртка аэродинамического профиля, коэффициенты, частоты и
  длины волн из опытов, таблицы испытаний).
- Снимите таблицы: OCR текстового скана + ручная сверка, либо ручная
  транскрипция с изображений; сохраняйте пруф (скрин/фрагмент + координата
  «файл · фрагмент #N» для корпуса, либо страница трещины книги + ссылка на
  страницу архива).
- Весь сырой материал положите в `raw/` с пометкой источника.

**Результат:** `raw/*.tsv` + `03-extraction-log.md` (что извлечено, из какого
источника, точность OCR, что пропущено и почему).

## Этап 3. Нормализация в единую схему и валидация

- Приведите к одной схеме (см. `30-dataset-spec-template.md`): одинаковые
  единицы, понятные имена колонок, строки-происхождения.
- Сделайте автоматические проверки: нет пустых строк, единицы согласованы,
  каждая строка ссылается на источник; добавьте ручную выборочную сверку с
  книгой (не менее 5 % строк).
- Где нужно — переформулируйте заголовки/подписи своими словами, если книга
  ещё охраняется (или оставьте точные из PD-книги).

**Результат:** `data/<dataset>.csv/.parquet` (готовый), `04-validation.md`
(метрики валидации + скрин проверки с источником), файл лицензии и README.

## Этап 4. Публикация на Kaggle

- Заведите аккаунт Kaggle, создайте **Dataset** (см. `40-kaggle-publish.md`):
  загрузите файлы, заполните описание, выберите **лицензию CC0-1.0** (или
  PDDL) и теги (aviation / radar / history-of-science).
- Приложите README датасета и **baseline-ноутбук** (пример чтения и быструю
  метрику), чтобы другим было с чего начать.

**Результат:** рабочая ссылка на Kaggle Dataset + скрин карточки с указанием
лицензии; у каждого члена команды должна быть хотя бы одна собственная правка
(леф-об).

## Этап 5. Соревнование сообщества

- Команда-«организатор» выбирается из желающих и подготавливает чек-лист
  соревнования (см. `45-community-competition.md`): задача/целевая метрика,
  «приватный» тестовый подвыбор (для честной проверки), правила (что
  разрешено/запрещено), дедлайн, форма подачи решения.
- Остальные команды выставляют прогнозные модели/методы на основе
  опубликованного датасета и одновременно публикуют свои версии данных.

**Результат:** `05-competition.md` (правила и метрика) + таблица результатов
(участник, метод, метрика на приватном тесте, ссылка на ноутбук).

## Этап 6. Отчёт и рефлексия

- Финальный отчёт (I страница на команду) и короткая презентация: что
  извлечено, что было сложно, чему научились, какие улучшения предложили бы
  архивам/кагглерам.

## Критерии оценки (сквозные)

| Критерий | Вес | Что смотрим |
|---|---|---|
| Правовая прозрачность | 30 % | чек-лист пройден, лицензия корректна, атрибуция по строкам |
| Достоверность и прослеживаемость | 25 % | сверка с источником, provenance, полные координаты |
| Качество данных | 20 % | схема, единицы, отсутствие дублей/мусора, авто-валидация |
| Публикация и участие | 15 % | Kaggle Dataset с лицензией, baseline, участие в соревновании |
| Документация/этика | 10 % | полный комплект файлов модуля, отсутствие фабрикации |
